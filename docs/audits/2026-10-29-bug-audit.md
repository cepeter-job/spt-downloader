## 2. Findings

### F1 — Verified: `FinancialPost._route` BaseException containment does not re-raise

- **Location:** `coretax_financial_post.py`, `FinancialPost._route`, `except BaseException as error:` (line 262).
- **Verified excerpt (line 262):** `except BaseException as error:`
- **Verified control flow:** `KeyboardInterrupt`/`SystemExit` are BaseException instances, not `Exception`. The handler therefore takes the non-Exception path: sets `self.invalid = True`, stores the BaseException in `self.stopped` (line 271), and performs best-effort `route.abort('blockedbyclient')` (lines 273–275). No re-raise occurs before `_route` returns.
- **Design anchor:** `docs/audits/2026-10-29-exception-inventory.md` classifies this site as BaseException → cleanup/rollback + Stop propagation; decision text: "rethrow or preserve terminal cancellation. No completion grant."
- **Assessment:** the handler preserves terminal state via flags instead of re-raising. Whether the Ctrl+C/Stop contract is satisfied depends on Stop propagation through the owning observer/finally path; not fully resolved by source at audit time.
- **Resolution (2026-10-29, external auditor verification):** deferred, no production change. Auditor: cancellation is stored in `self.stopped` and subsequently propagated via `FinancialPost.check()`; existing regression tests (`test_stop_after_button_capture_prevents_post_replay`, `test_stop_cleans_the_scoped_route_and_browser_stream`) cover the Stop contract.

### F2 — `_publish_output` rollback failure converts BaseException to RuntimeError (Verdict: CONFIRMED — FIXED)

- **Location:** `coretax.py`, `_publish_output`, inner `except BaseException as recovery_error:` (line 361), re-raise site (line 363).
- **Verified excerpt (line 363):** `raise RuntimeError(f'Output rollback blocked; recovery files retained at {staging}') from recovery_error`
- **Verified control flow:** outer handler (line 350) uses bare `raise` (line 364); the inner handler intercepts rollback failures and raises `RuntimeError` (chained via `from recovery_error`). An interrupt raised during rollback is therefore converted into a `RuntimeError`, losing the original exception class.
- **Comment (line 362):** `Kunci eksternal atau interupsi juga bisa menghalangi rollback.`

- **Resolution (2026-10-29, TDD):**
  - Focused regression test added: `tests/test_output_safety.py::test_interrupt_during_rollback_propagates_interrupt_and_retains_recovery` — expects `KeyboardInterrupt` during rollback interruption, asserts recovery directory retained.
  - RED: test failed as predicted — interrupt during rollback surfaced as `RuntimeError` (regression confirmed).
  - Fix: `coretax.py` inner handler now wraps only `Exception` in `RuntimeError`; bare `raise` re-raises BaseException (interrupt) untouched. Recovery retention preserved (staging dir retained on interrupt path).
  - Updated existing contract test `test_interrupt_in_rollback_probe_keeps_recoverable_original_files` to expect `KeyboardInterrupt` (interrupt propagates; recovery retained) — aligned with the fix.
  - Re-run: rollback-related suites (`test_output_safety.py`, `test_publication_crash_recovery.py`, `test_financial_publication.py`) → all green (exit 0). `ruff` on changed files: ok.
