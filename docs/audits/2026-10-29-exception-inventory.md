Regenerate against any current checkout with `python scripts/quality_inventory.py --output <scratch>/quality.json`; this command parses Git-tracked source and imports no product modules. Line numbers below describe the reviewed source snapshot and may move.

**105 non-test broad handler sites.** Count only bare catches or handlers explicitly naming `Exception`/`BaseException`, including tuple members. Subclasses such as `DecimalException` are specific errors and excluded. The initial scratch counter included one such subclass; the corrected definition is authoritative. Test handlers are inventoried by the script but excluded from this production/tooling table.

Expected failures use their existing typed exceptions (`OSError`, JSON/value errors, Playwright timeout/error, queue.Full/Empty). Retained broad sites below are containment, not a catalog of expected exceptions. Their callback/driver/ZIP implementations can raise heterogeneous errors; mechanically narrowing them would remove cleanup or turn safely unavailable proof into a different product outcome. BaseException is limited to cleanup/rollback/Stop preservation. No handler may reinterpret unknown evidence as COMPLETE.

The three priority owners were inspected individually: browser errors retain fixed capture categories; JSON capture reads/driver probes mark unavailable/failed proof, with cleanup separated; diagnostics have a closed type/frame/field sanitizer and optional queue/store lifecycle. CLI fault injection covers checkpoint ENOSPC, permissions, locked replacement, original exit1/130, cleanup continuation and partial startup acquisition. Detail tests now reject raw messages and hostile string conversion. Existing auth/capture/provenance negative tests remain in the full Windows inventory.
