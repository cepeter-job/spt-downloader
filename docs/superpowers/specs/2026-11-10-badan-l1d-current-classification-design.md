## Narrow supported change

Keep the legacy explicit outer `BusinessClassification == BC04` route.
For an **absent outer key only**, admit the current classification only with:

- existing validated submitted/non-history literal route, model/list/source
  identity, original current source and component lifetime;
- preceding observed Induk;
- exact string `CurrentFormData.MainFormData.BusinessClassification == BC04`;
- optional L1-D projection marker `visibility_binding=current-induk-enabled-v1`,
  emitted only after independently rechecking the enabled exact L1-D tab,
  connected visible form, unique same-view panel ownership and route on both
  sides of L1-D observation;
- unchanged loaded provider hashes, id-ID/Asia/Jakarta, three table owners,
  headers, spans, source shape, safe numeric types and all reconciled totals.

Do not reinterpret explicit outer null, malformed or conflicting classification
as absence. Unknown explicit marker, absent/malformed/current non-BC04 data or
missing enabled-form proof refuses. A present current classification that
contradicts the admitted legacy outer classification also refuses. Never trust
a caller's raw classification hint or browser business value.

Retain the optional visibility marker in projection provenance for replay.
Validate it at the adapter boundary, not only at the observer emitter.
